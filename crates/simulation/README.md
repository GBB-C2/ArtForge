# Жидкость: CPU PBF

`poseforge-simulation` — детерминированный CPU-решатель жидкости на частицах. Он использует фиксированное физическое время, сохраняет импульс при вязкости, обрабатывает совпадающие частицы и уточняет поверхность без увеличения числа полигонов. Это экспериментальный инструмент предпросмотра; GPU-решатель и взаимодействие со скинированными мешами не реализованы.

## Контейнер по форме меша

`mesh_contact::MeshVolume` проверяет замкнутость поверхности с учётом UV-швов и строит BVH. `FluidWorld::set_container` ограничивает частицы этой поверхностью; сигнатура кэша включает её геометрию. Поверхность жидкости также ограничивается контейнером. В приложении жидкость назначается примитиву, материал и поверхность видны автоматически. [Изменения и статус проверки 0.34.0](../../docs/PHYSICS.md).

## Решатель

Внешний физический такт по умолчанию равен **1/120 с**. Внутри такта количество подшагов определяется скоростью частиц, гравитацией и движением препятствия. За один подшаг решатель стремится ограничить относительное перемещение радиусом частицы. `max_substeps` ограничивает стоимость; `StepReport::substep_limit_reached` сообщает, если запрошенной детализации не хватило. Частота кадров окна не участвует в выборе физического шага, поэтому повторный расчёт и перемотка по кэшу воспроизводят одно состояние.

Плотность корректируется PBF-итерациями с Poly6 и Spiky. Пространственный индекс использует упорядоченные ячейки и общий плоский массив соседей; рабочие массивы переиспользуются. Индекс перестраивается после каждой коррекции, поэтому переход частицы в соседнюю ячейку учитывается следующей итерацией. Для численно совпадающих частиц используется детерминированный антисимметричный градиент: сжатая пара больше не застревает из-за нулевого направления. Обычные расстояния сохраняют исходное ядро.

Вихревое ограничение восстанавливает часть вращательного движения, которое теряется при численном решении. Оно применяется после обновления скоростей и не добавляет вращение в однородный поток. XSPH-вязкость теперь обменивает скорость попарно, с равными и противоположными приращениями. Симметричная нормировка учитывает обе соседние области: вязкость сохраняет суммарный импульс, не разгоняет центр массы при неоднородной плотности и уменьшает кинетическую энергию. Однородный поток и изолированные частицы остаются неизменными. XSPH-вязкость и трение пересчитываются по длине подшага: добавление подшагов не должно само по себе увеличивать затухание. Скорость и вихревое ускорение имеют численные ограничения; это средства устойчивости предпросмотра, а не точная физическая калибровка.

Метод основан на [Macklin, Müller — Position Based Fluids](https://mmacklin.com/pbf_sig_preprint.pdf), в частности на вихревой коррекции и XSPH из раздела 5. Здесь сохраняются ограничения только положительного сжатия: физическое поверхностное натяжение и когезия не моделируются.

## Параметры

| Поле `FluidConfig` | Значение по умолчанию | Допустимый диапазон |
|---|---:|---:|
| `time_step` | 1/120 с | 1/1000…1/30 с |
| `iterations` | 4 | 1…16 |
| `max_substeps` | 4 | 1…8 |
| `viscosity` | 0.04 | 0…0.2 |
| `vorticity` | 0.1 м/с | 0…5 |
| `boundary_friction` | 0.05 | 0…1 |
| `gravity` | (0, −9.81, 0) м/с² | конечный вектор длиной не более 1000 |
| `max_speed` | 8 м/с | 0.1…100 |

Новые поля получают значения по умолчанию при чтении старого JSON-конфига. Изменение параметров через `set_config` или `reconfigure` сначала проверяется целиком, затем сбрасывает частицы в исходное состояние и инвалидирует кэш. Неизменённая конфигурация ничего не сбрасывает. `demo_with_config(config)` создаёт прежний объём из 576 частиц и колеблющуюся сферу с выбранными параметрами.

## Контакты и время

Контейнер замкнут со всех шести сторон, координаты заданы в метрах, Y направлена вверх. Относительная траектория частицы и сферы проверяется на пересечение в течение подшага, поэтому быстрое линейное движение не ограничивается проверкой только конечной позиции. Колебательное движение сферы приближается линейным внутри каждого подшага. Это не непрерывная проверка произвольной геометрии. Если сфера пересекает стенку, приоритет имеет удержание частицы в контейнере.

`advance(delta_seconds, max_steps)` ограничивает вызов 64 физическими тактами и очередь реального времени двумя секундами. Непросчитанный остаток возвращается как `backlog_seconds`, отброшенное настенное время — как `discarded_seconds`. Это предотвращает неограниченное накопление работы в интерактивном предпросмотре. `step()` и offline-кэш `CacheTimeline::bake()` время не отбрасывают.

Фоновый предпросмотр приложения обрабатывает до **8 тактов за пакет** вместо прежних двух: при доступной производительности это позволяет поддерживать скорость времени 2× даже при обновлении окна 30 Гц. Пакеты не блокируют UI; отмена проверяется между тактами. Если расчёт медленнее требуемого, действует прежний ограниченный бюджет очереди, поэтому это не гарантия реального времени.

Для фонового потока предусмотрен `advance_cancellable(delta_seconds, max_steps, &AtomicBool)`. Отмена происходит между завершёнными тактами, а не посреди PBF-итерации. `StepReport` содержит число тактов и подшагов, отмену, ограничения, максимальную плотность и вихрь, число проверенных соседних кандидатов.

```rust
use poseforge_simulation::{CacheTimeline, FluidConfig, FluidWorld};

let config = FluidConfig { vorticity: 0.2, ..FluidConfig::default() };
let mut world = FluidWorld::demo_with_config(config).unwrap();
let mut cache = CacheTimeline::new(&world);
for _ in 0..120 {
    world.step();
    if world.tick() % 4 == 0 { cache.record(&world).unwrap(); }
}
assert!((world.time() - 1.0).abs() < 1e-6);
cache.seek(&mut world, 60).unwrap();
```

## Поверхность и кэш

`extract_surface(&world, cell_size, iso_density)` извлекает плотностную изоповерхность marching tetrahedra. Общие пересечения рёбер используют одну индексированную вершину, нормали сглаживаются. Тонкие ненулевые грани сохраняются. Если обрезка контейнером схлопывает грань на ребро коробки, соседняя грань разбивается по существующим вершинам: это закрывает стыки без нулевых треугольников. Для демонстрации после 120 тактов проверены оба размера ячейки 0.045 и 0.025 м: каждое ребро принадлежит двум граням.

`extract_surface_cancellable(..., &AtomicBool)` проверяет отмену при вычислении поля, построении и сшивке треугольников, нормализации нормалей; частичная поверхность не возвращается. В объектном режиме результат автоматически обновляет временную поверхность жидкости; отдельная команда снимка прежней демонстрации создаёт статический меш. Внутри контейнера пересечение рёбер уточняется монотонной кубической интерполяцией Эрмита с аналитическими градиентами плотности; 12 ограниченных шагов сохраняют скобку пересечения. Общие вершины остаются побитно одинаковыми. На искусственном разрыве поля за стенками сохраняется линейная интерполяция, чтобы не менять закрытие контейнера. Тест аналитической Poly6-капли проверяет уменьшение ошибки радиуса более чем в 10 раз на заданном сечении; это не универсальная оценка любой сцены.

До выделения поля проверяется предел **500 000 ячеек**, для геометрии — **1 000 000 вершин** и **2 000 000 треугольников**. Для демонстрационного контейнера минимальный предлагаемый в интерфейсе размер ячейки 0.025 м укладывается в этот бюджет даже при заполнении всей области. Уменьшение ячейки повышает стоимость; перестраивать такую поверхность каждый кадр на UI-потоке не следует.

Контрольная точка хранит позиции и скорости. Кэш связан с версией решателя и всеми исходными параметрами; новая версия `artforge-cpu-pbf-5` отвергает прежние физические кэши. `save_new(path)` создаёт новый файл и не перезаписывает существующий. Предел загрузки JSON-кэша — 256 МиБ. Отмена, загрузка повреждённого кэша или невалидная конфигурация не заменяют текущее состояние частично.

## Проверка

```text
cargo test -p poseforge-simulation --locked
cargo run -p poseforge-simulation --example profile --release --locked
```

26 тестов проверяют устойчивость и границы контейнера, повторяемость при разной частоте окна, перемотку, сжатую плотность, быструю движущуюся сферу, вихрь и однородный поток, сохранение импульса и диссипацию энергии вязкостью, разделение совпадающих частиц, точность криволинейной поверхности, контактное трение, бюджеты времени, отмену и замкнутость индексированной поверхности, включая контакт с углами контейнера. `profile` отдельно измеряет 120 тактов демонстрации и извлечение поверхности. Условия и результаты измерения приведены в [SIMULATION_PROFILE.md](../../docs/SIMULATION_PROFILE.md). Численные тесты не устанавливают FPS приложения и не заменяют визуальную проверку на целевой машине.

## Дополнения 0.8

Формы и центр/размер источника редактируются в проекте. Коллайдеры сцены передаются в PBF как до 64 мировых AABB; swept slab test ограничивает прохождение частицы сквозь тонкий объём. Изменение коллайдеров меняет сигнатуру кэша. Версия решателя `artforge-cpu-pbf-5` отклоняет прежние кэши.

Модуль `deform` реализует экспериментальную XPBD-ткань и сокращаемую оболочку мышцы: растяжение, диагональные/изгибные связи, закреплённый край, 8 итераций при 120 Гц, контакты с полом и AABB. Нет самостолкновений, анатомии, skin/morph и двусторонней связи с жидкостью. Фоновый предпросмотр записывается в документ только явным снимком меша. Описание управления — в [ARTWORK.md](../../docs/ARTWORK.md).
