# Импорт Blender в ArtForge Studio 0.7.0

**Обычный импорт `.blend` загружает модель, поддерживаемые материалы и текстуры, скелет с весами и геометрию shape keys.** Готовые анимационные клипы включаются отдельно; по умолчанию запекание всего диапазона кадров не выполняется. Импортированный скелет можно позировать и анимировать в ArtForge Studio.

Blender запускается **в фоне без открытия окна**. ArtForge Studio получает временный GLB и передаёт его проверенному импортёру. В Windows процесс дополнительно запускается без консольного окна. Отдельная настройка фонового запуска не требуется.

| Файл | Нужен установленный Blender | Что делает ArtForge Studio |
|---|---|---|
| `.blend` | Да | Загружает модель, текстуры и скелет; готовая анимация — по отдельному выбору |
| `.glb` / `.gltf` | Нет | Импортирует модель и поддерживаемую анимацию напрямую |
| `.obj` | Нет | Импортирует геометрию и поддерживаемые MTL-материалы напрямую; скелетной анимации в OBJ нет |
| `.poseforge` | Нет | Открывает сохранённый проект |

Если Blender не установлен, используйте GLB/glTF или OBJ. Для повторной работы с однажды импортированным `.blend` сохраните `.poseforge`: этот проект затем открывается без повторного преобразования и без Blender. Исходный `.blend` не перезаписывается.

Режим запуска, аргументы, очистка временных файлов и отмена проверяются контрактными тестами. Актуальные результаты запусков, использованные версии Blender и ограничения проверки на Windows перечислены в [VALIDATION.md](VALIDATION.md). Контрактные тесты не заменяют проверку реального файла и поведения окон на целевой машине.

## Режимы импорта

В панели «Проект» → «Импорт» есть флажок **«Импортировать готовую анимацию (.blend)»**:

| Выбор | Переносимые данные |
|---|---|
| Выключен — начальное значение | Модель, UV, поддерживаемые материалы и изображения, деформирующий скелет с весами, геометрия shape keys; исходные клипы не экспортируются |
| Включён | Те же данные и вычисленное движение активной сцены за её диапазон кадров, с покадровым запеканием SCENE |

Кости и веса сохраняются в обоих режимах. Для создания собственной анимации достаточно обычного режима модели. Выбранное значение флажка сохраняется в настройках рабочего пространства и действует также при открытии `.blend` в интерфейсе и перетаскивании файла. Фоновая задача запоминает значение при запуске. Настройка относится только к `.blend`; прямой импорт GLB/glTF/OBJ не меняется.

Режим модели исключает работу по экспорту исходных клипов. Время чтения геометрии, упаковки текстур и проверки результата всё ещё зависит от файла; универсальное ускорение в определённое число раз не задаётся.

## Настройка и запуск

1. Установите Blender 3.6 или новее. Сборка должна содержать glTF-экспортёр с необходимыми режимами; скрипт проверяет его свойства и прекращает импорт при несовместимости.
2. В ArtForge Studio откройте «Проект» → «Импорт». Укажите `blender.exe` в поле пути к Blender на месте, вставьте путь из буфера или нажмите «Обзор…». Поддерживаются Unicode, пробелы и парные внешние кавычки. Для обычной установки автопоиск может найти его сам; пустое поле возвращает автопоиск.
3. Нажмите «Проверить» рядом с путём Blender. Эта команда проверяет найденный путь; версия и возможности экспортёра проверяются при настоящем преобразовании.
4. Для модели с текстурами и скелетом оставьте флажок готовой анимации выключенным. Если нужны исходные движения, включите его перед импортом. Выберите `.blend` или перетащите его в свободное от диалогов окно; дождитесь импорта либо отмените операцию через Esc.
5. Проверьте отчёт о материалах и риге, затем подтверждайте назначения в панели «Персонаж».

Порядок поиска: путь из настроек → `POSEFORGE_BLENDER` → `PATH` → обычные каталоги Blender Foundation в Program Files на Windows. На macOS также проверяется `/Applications/Blender.app`. Неверный явно указанный путь вызывает ошибку; другая установка вместо него не выбирается автоматически.

Пример настройки в PowerShell — замените путь на свой:

```powershell
$env:POSEFORGE_BLENDER = 'C:\Program Files\Blender Foundation\Blender 4.5\blender.exe'
cargo run --release --locked -- --convert-blend character.blend output/character.poseforge
cargo run --release --locked -- --detect-skeleton output/character.poseforge
```

Для переноса готовой анимации либо отчёта об этом режиме:

```powershell
cargo run --release --locked -- --convert-blend character.blend output/character-animated.poseforge --animations
cargo run --release --locked -- --import-report character.blend --animations
```

Команда `--convert-blend` создаёт новый выходной файл и отказывается заменять существующий. Используйте локальную папку; если файловая система не поддерживает безопасную публикацию результата, сохраните его локально и затем перенесите.

CLI использует переменную окружения или автопоиск Blender. Путь и флажок, сохранённые интерфейсом, предназначены для GUI. В CLI исходные клипы добавляются только явным `--animations` в `--convert-blend INPUT.blend OUTPUT.poseforge [--animations]` или `--import-report MODEL [--animations]`; применение этого флага к GLB/glTF/OBJ отклоняется.

Прямые команды рендера и проверки также принимают `.blend`, но используют обычный режим модели и каждый раз выполняют преобразование. Для рендера исходной анимации сначала создайте `.poseforge` через `--convert-blend ... --animations`, затем передайте сохранённый проект команде рендера.

## Ход работы и отчёт

Во время работы Blender отображаются этапы «Запуск Blender», «Открытие .blend», «Подготовка модели в Blender» и «Экспорт модели, текстур и скелета». При включённых клипах последний этап называется «Экспорт модели и запекание анимации». Рядом показано прошедшее время. Пока точная доля готовности неизвестна, индикатор не выдаёт постоянные «10%» за измеренный прогресс. После завершения Blender появляются процентные этапы чтения и проверки GLB.

«Отчёт последнего импорта» указывает выбранный профиль и измеренное время открытия/экспорта. Для передачи диагностики используйте «Копировать отчёт»: скопируются все страницы. Само ожидание на этапе экспорта не устанавливает причину задержки; длительность нужно оценивать вместе с содержимым сцены и результатами измерения.

## Ошибка export_format=GLB и применение исправления

Если трассировка заканчивается в функции `export_options` сообщением `glTF exporter does not support export_format=GLB`, этот отказ сформировала **предварительная проверка ArtForge Studio**, до вызова оператора экспорта. В прежнем коде пустой список значений RNA ошибочно считался признаком несовместимости.

У параметра может быть динамический список, вычисляемый функцией при работе оператора. В [исходниках glTF-Blender-IO](https://github.com/KhronosGroup/glTF-Blender-IO/blob/main/addons/io_scene_gltf2/__init__.py) `export_format` использует `items=get_format_items`, а сама функция содержит вариант GLB. [Описание EnumProperty в API Blender](https://docs.blender.org/api/current/bpy.types.EnumProperty.html) различает сведения о значениях перечисления и динамическую генерацию; список также может содержать элементы оформления интерфейса. Поэтому неизвестный список сам по себе не доказывает отсутствие поддержки нужного значения.

Исправленный адаптер сохраняет запрошенный **GLB** и, при включённых клипах, режим **SCENE**. Если список пуст или содержит только разделители без идентификаторов, значение передаётся оператору Blender, который окончательно принимает его либо сообщает ошибку. При непустом известном списке неподдерживаемое обязательное значение по-прежнему отклоняется; отсутствие обязательного свойства также останавливает импорт. Необязательное значение с известным несовпадением пропускается. Автоматической смены формата или отключения обязательных возможностей нет.

**Для применения исправления нужно пересобрать ArtForge Studio.** Файл `crates/io/scripts/export_blend.py` встраивается в программу через `include_str!` во время сборки.

1. Закройте запущенный ArtForge Studio и обновите исходники в папке проекта с `Cargo.toml`.
2. Запустите `START_WINDOWS.cmd` из обновлённой папки: он выполняет `cargo build --release --locked` и затем запускает полученный EXE. Требования к среде описаны в [START_HERE_RU.md](../START_HERE_RU.md).
3. Повторите импорт. Если возникает ошибка, откройте отчёт операции и используйте «Копировать отчёт», чтобы получить полную диагностику.

При ручной сборке выполните из корня обновлённого проекта:

```powershell
cargo build --release --locked
.\target\release\artforge.exe
```

Путь к `export_blend.py` во временном каталоге, в том числе внутри `.inkcode/tmp`, обозначает рабочую копию скрипта. Каждый импорт создаёт её заново из содержимого исполняемого файла; изменение этой копии не обновляет программу. По имени папки в трассировке нельзя определить версию запущенной сборки. Запускайте EXE, полученный из обновлённых исходников.

Это исправление устраняет конкретный ложный отказ предварительной проверки. Совместимость конкретного файла и версии Blender требует проверки на целевой машине. Актуальный объём выполненных проверок — в [VALIDATION.md](VALIDATION.md).

## Что переносится

| Данные | Поведение адаптера |
|---|---|
| Сцена | Активная сцена Blender, включая скрытые объекты; не все сцены файла |
| Геометрия и текстуры | Экспорт в GLB, далее ограничения импортёра ArtForge Studio |
| Скелет | Деформирующие кости и необходимые связи, skin и bind-данные экспортёра |
| Анимация | При включённом флажке или `--animations`: вычисленная активная сцена за текущий диапазон кадров, с покадровым семплированием; по умолчанию клипы не экспортируются |
| Shape keys | Геометрия morph-целей в обоих режимах; их исходное движение — только с анимацией. Модификаторы не применяются принудительно |
| Материалы | glTF-представление: цвет, metallic/roughness, normal, AO и emission; KHR_materials_emissive_strength |
| Свет | Запрошен экспорт lights: направленные, точечные и spot через KHR_lights_punctual; статическое положение |
| Камеры | Запрошен экспорт камер; все экспортированные glTF-камеры сохраняются как узлы с объективом, первая активна в импортируемом проекте |

Неиспользуемые Actions, другие Blender-сцены, исходная система constraints/drivers, управляющие виджеты, Geometry Nodes, процедурные материалы, area/world lights и эффекты Blender не воспроизводятся как полноценные аналоги в ArtForge Studio. При включённой анимации результат части ограничений может попасть в запечённые трансформации; их редактируемая логика не переносится.

Скрипты исходного `.blend` не выполняются автоматически. Поэтому Python-драйверы и зависимости от пользовательских дополнений могут не вычислиться. Для такой модели заранее подготовьте совместимую геометрию и исходную позу; для переноса движения может потребоваться отдельное запекание в Blender. ArtForge Studio показывает предупреждения о блокировке скриптов и неподдерживаемых данных.

Источники света не анимируются вместе с импортированными каналами. Их можно выбирать и перемещать гизмо в сцене либо менять в категории «Свет» вкладки «Объект» через числовые поля и «Расположить перед камерой». До восьми источников могут быть включены одновременно; при добавлении к существующей сцене учитываются и её источники. Тени, HDR-окружение и эффекты освещения Blender не переносятся.

Общий для карт материала UV-набор переносится в UV меша; при разных наборах выбирается минимальный индекс, несовместимые карты пропускаются с предупреждением. `KHR_texture_transform` сохраняется отдельно для каждой карты; sampler-настройки сохраняются отдельно для каждой карты. `COLOR_0`, если его передал экспортёр Blender, сохраняется как линейный множитель RGBA. Не всякий узловой материал Blender переводится в glTF: подготовьте совместимые карты и проверьте отчёт. После загрузки выберите меш и откройте «Свойства» → «Материал».

Дробный FPS для подготовленного проекта округляется до целого диапазона 1–240 с предупреждением. При добавлении сцены в уже открытый проект сохраняется FPS этого проекта. Если перенесены клипы, их время остаётся в секундах; исходные номера кадров Blender и ArtForge Studio могут различаться.

## Ограничения и ошибки

- До 2 ГиБ на входной `.blend`; временный GLB должен уложиться в обычные лимиты импортёра.
- Прежний лимит 256 суставов снят. До 65 536 записей на skin, общий предел glTF — 10 000 узлов; четыре ненулевых влияния на вершину. Бюджет матриц с учётом экземпляров — 64 МиБ. Риг из 623 костей больше не отклоняется только из-за их количества; прочие требования импорта сохраняются.
- Модификаторы меша не применяются принудительно ради сохранения shape keys; итоговую геометрию необходимо проверить на реальном файле.
- Несовместимый экспортёр, неподдерживаемое обязательное glTF-расширение или превышение лимитов приводит к объяснимому отказу. Импорт не добавляет в сцену частичный результат.
- Преобразование ограничено 10 минутами. Отмена/тайм-аут останавливает Blender и очищает временные файлы. Исходный `.blend` не сохраняется ни при успехе, ни при отмене.

Это не матрица сертифицированной совместимости версий Blender. Минимальная версия и наличие RNA-параметров проверяются кодом; реальный корпус файлов ещё требуется.

## Для разработчика

Процесс запускается через аргументы `Command`, без командной оболочки, с `--background`, `--factory-startup`, `--disable-autoexec` и `--python-exit-code`. `--background` включает выполнение без пользовательского интерфейса; на Windows дополнительно используется `CREATE_NO_WINDOW` (`0x08000000`) для консольного процесса. Ввод процесса закрыт, stdout/stderr направлены во временный журнал; сообщения о ходе работы и ошибках показывает ArtForge Studio. Встроенный скрипт дополнительно открывает файл с `load_ui=False, use_scripts=False`. Экспортёр проверяется через RNA: отсутствующие необязательные параметры не передаются, отсутствие обязательных свойств прекращает операцию. Для ENUM предварительное сравнение применяется только к непустому набору идентификаторов; пустые идентификаторы элементов интерфейса отбрасываются. Окончательную проверку переданных значений выполняет оператор. Выбор EXE и этот режим не являются песочницей для самого Blender.

`BlendImportOptions::default()` выбирает профиль модели. Python-мост получает три пути и только при запросе клипов дополнительный `--animations`. Для модели обязательны возможности экспорта skin, morph-геометрии, материалов, изображений и UV; анимационные требования добавляются для соответствующего профиля. Служебный JSON содержит `import_profile` (`MODEL`/`ANIMATION`), `animations_exported`, `animation_mode` (`NONE`/`SCENE`) и `timings_seconds` для открытия, подготовки, экспорта и всей работы моста. Rust проверяет соответствие отчёта запрошенному профилю.

Строки `POSEFORGE_STAGE:…` сбрасываются в stdout при смене этапа. Rust читает новые данные ограниченными порциями и принимает только известные маркеры протокола. Неопределённая стадия Blender передаётся callback прогресса отрицательным значением; GUI/CLI показывают её название и прошедшее время. Обычные доли прогресса возвращаются при чтении GLB.

Контрактные тесты используют подставной `bpy` и не запускают Blender:

```text
python -m unittest discover -s crates/io/tests -p test_export_blend.py -v
```

Тесты различают профили модели и анимации, неизвестный динамический список и явную несовместимость, проверяют передачу GLB и условного SCENE, отсутствие повторного экспорта с другими настройками и сохранность исходного файла. Исключение оператора, `CANCELLED`, `FINISHED` без файла или с пустым GLB не должны создавать успешный JSON-отчёт.

Для настоящей проверки нужен Blender: сравнить оба режима на подготовленных `.blend`. В режиме модели должны сохраниться UV, изображения, материалы, skin и morph-геометрия при отсутствии исходных клипов; с `--animations` дополнительно проверяются ключевые кадры. Нужны также проверки отмены, двух персонажей и сохранения в `.poseforge`. Rust-тесты процесса и ручная проверка дополняют Python-тесты; итоговые выполненные проверки перечислены в [VALIDATION.md](VALIDATION.md).
