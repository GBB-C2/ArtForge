# Производительность моделирования 0.22

## Фоновая работа и запуск

- Подготовка контейнера жидкости, посев частиц и первая поверхность выполняются в потоке. Назначение применяется целиком после успешного результата; Esc и изменение сцены предотвращают применение устаревшего результата.
- При открытии сцены запускаются максимум две задачи инициализации контейнеров одновременно. Отменяемые задачи занимают слот до завершения. Одинаковая неудачная конфигурация не пересчитывается на каждом кадре.
- Закрытие кэша миниатюр посылает отмену и не ожидает занятую GPU-задачу на потоке окна. Рабочий поток освобождает свои ресурсы после завершения текущего чтения GPU.
- Опрос активных фоновых операций использует срок следующего кадра, без безусловного запроса перерисовки перед ожиданием. Истёкший срок автосохранения не создаёт непрерывный цикл.
- Приглушение исходных значений сброса обходит список прямоугольников интерфейса один раз, вместо повторного прохода для каждой кнопки.
- Геометрия стартового персонажа читается один раз; новые сцены разделяют неизменяемые буферы до редактирования. Модель содержит 13 432 вершины и 26 704 треугольника рендера.

Эти изменения устраняют конкретные блокировки и лишнюю работу по анализу кода. FPS, длительность GPU-операций и запуск Windows здесь не измерялись. [Проверки](VALIDATION.md).


Оптимизации касаются редактируемой сетки и её интерфейса. Они не являются замером FPS всего рендера.

| Участок | Изменение |
|---|---|
| Отображение сетки | Одно ребро передаётся одним GPU-примитивом с отсечением и сглаживанием в шейдере; CPU больше не раскладывает его в множество маленьких прямоугольников. |
| Проекция вершин | Матрица камеры и область просмотра вычисляются один раз на проход сетки или выбора, а не для каждой вершины. |
| Связность | Позиционно объединённые вершины, рёбра и соседние грани кэшируются по ревизиям меша. |
| Проверка перекрытия | Для выбора используется кэш BVH. С 0.22.6 отображение компонентов сравнивается с глубиной сцены на GPU: без CPU-луча на каждый пиксель и без дополнительных примитивов на ребро. Проход глубины нужен только при включённой проверке; X-Ray её обходит. |
| Выбор связанных рёбер | Обход через вершины не создаёт список всех пар рёбер, сходящихся в одной точке. Тест использует веер из 10 000 треугольников. |
| Жест мыши | Предпросмотр вычисляется от исходной геометрии. Полная валидация документа и завершение истории выполняются при подтверждении; промежуточные события проверяют изменённый меш. |
| GPU-ресурсы | Изменение вершин/индексов обновляет ресурсы по ревизиям, не сбрасывая все текстуры и привязки материалов. |

Тест плотной сферы с подразделениями 48 × 48 на каждой стороне проверяет 13 824 четырёхугольные грани и 27 648 уникальных рёбер. Для непустого вида число линий не превышает число рёбер; кэш связности переиспользуется до изменения геометрии. Во время жеста изменившаяся геометрия обновляет кэш: это не обещание постоянной стоимости для любых размеров сцены.

Измерение CPU-прохода можно повторить после сборки:

```sh
cargo test -p artforge mesh_cache_reuses_adjacency_and_overlay_has_one_gpu_primitive_per_edge -- --nocapture
```

Тест печатает число граней, рёбер, UI-примитивов и время построения наложения. Это единичный замер оптимизированного тестового профиля с подготовленной связностью; он не включает GPU-кадр, загрузку материалов, нативное окно или сравнение с 0.20. Аппаратный FPS и скорость на Windows в этой среде не измерялись. [Фактические проверки](VALIDATION.md).
